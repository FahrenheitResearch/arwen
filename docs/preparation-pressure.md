# Surface-pressure initialization

The existing `case_data.sfcp_to_sfcp` boolean selects a shared initialization operation. `true` adjusts the analyzed surface pressure from source terrain to model terrain with `sfcprs2`. `false` reconstructs it from sea-level pressure and the pressure/geopotential-height profile with WRF's `sfcprs3`. It does not copy the input surface pressure unchanged.

Both operations retain the original analyzed surface pressure and source terrain for the column-moisture integration and surface interpolation anchor. The sea-level route also needs `PMSL` in pascals and at least two atmospheric levels. Invalid or unbracketed profiles identify the affected row and column.

For `gpuwm run --met-em DIR`, the producing namelist and actual file pressure order resolve the operation. WRF forces the surface-to-surface operation for an ascending hybrid pressure stack. On the descending pressure stack, `.false.` uses `FLAG_PSFC=1`, `FLAG_SOILHGT=1`, `FLAG_SLP=1` and the `PMSL` field. The Rust NetCDF reader converts explicitly labelled hPa to Pa. Missing declared inputs are reported before a forecast is initialized.

The shared Rust entry reads the existing float64 setup arrays and converts individual values to float32 for WRF REAL arithmetic. It follows a small level permutation and parallelizes independent columns; it does not materialize reordered full profiles or float32 copies of them. An unaligned array is aligned before crossing the native boundary. The existing `true` operation is unchanged and does not call this entry.

`tests/data/wrf-sfcprs3-fortran.json` records the independent WRF source/routine hashes, compiler flags, inputs and expected float32 bits. Its seven cases cover the sea-level threshold, ordinary brackets, exact isobaric height, WRF's excluded upper levels and lower-sea-level-pressure fallback. They match on Windows and Linux. These are initialization-operation controls, not a forecast-skill assessment. A matching rebuilt preprocessing library is required when the new operation is requested; existing ABI-v1 calls remain valid.


Native forcing can receive analyzed sea-level pressure from an explicit GRIB donor when the primary product does not contain it. Add `--supplement PMSL=/path/to/pressure.grib2` to the existing `gpuwm prep` native command. Repeat the binding for separate files, or provide one GRIB collection containing all requested source times. Each donor must be listed in the existing source-root `SHA256SUMS` manifest, whose digest is already passed to preparation. No neighboring files are discovered, and omitting a donor leaves ordinary native preparation unchanged.

The HRRR launch accepts the same binding: `gpuwm go CONFIG.toml --data-dir SOURCE_DIR --supplement PMSL=SOURCE_DIR/pressure.grib2`. Put each donor inside the chosen source directory and repeat `--supplement` for separate files. After fetching the primary inputs, `go` writes a separate run-local source manifest containing the fetched hashes and the explicit donor hashes. The fetch receipt remains intact, and preparation verifies all bound bytes before decoding. `--dry-run` validates the binding and prints a reusable launch command. An existing `--prepared-root` consumes its sealed fields and rejects new supplements.

The Rust selector accepts mean-sea-level PRMSL (0/3/1), and NCEP-center sea-level pressure parameters 0/3/192 and 0/3/198, which the [NOAA quantity table](https://www.nco.ncep.noaa.gov/pmb/docs/grib2/grib2_doc/grib2_table4-2-0-3.shtml) defines in Pa. It checks exact source cycle and forecast time, instantaneous representation, one provider per time, and the primary grid's complete projection and scan metadata. A different donor grid needs alignment before this native-window path can consume it. The donor is decoded by the same Rust GRIB engine and mapped by the existing projected mass-grid operator; no sea-level reduction is invented.

Publication retains the selected GRIB metadata, explicit donor paths and hashes, and the decoded PMSL hash. Donor bytes are checked again before sealing. Both live hourly preparation and sealed replay carry the field, including forcing-window extension. To extend a pinned window, preserve its existing donor files and add a new declared file for the new time; rewriting a pinned collection changes the sealed prefix. The selected `sfcp_to_sfcp` value remains authoritative: `.false.` still requires actual PMSL and never falls back to `.true.`.
