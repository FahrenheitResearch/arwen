# Regional background contract

The source catalog is derived from the existing source adapters, preparation
runners, product selectors, forcing grids and acquisition tables. Preparation
capability and automatic acquisition are separate facts. A source with supplied
input requirements may use its local handoff or a portable prepared bundle.

A selection records one cycle, requested initial time and complete final
boundary bracket. Fetch hours are a duration after the fetch start, while source
leads and model-relative forcing hours retain their existing meanings. Analysis
sequences carry absolute valid times. The analysis cadence remains an exact
whole-second duration; source boundary cadence follows its native input owner.

The ordinary local-DA command checks the actual declared transport objects
before publishing a review. It considers source cycles in newest-first order,
recalculates every required lead from the unchanged requested initialization,
and requires one endpoint to contain the initial frame, all intermediate frames
and the final bracket. For a 02 UTC initialization served from the preceding
18 UTC cycle, the first source lead is eight hours. Fetch hours remain the
duration after that lead. An explicit source cycle is attempted as requested;
an estimated publication delay alone cannot refuse it. Sources without an
object probe retain their native retrieval and inventory checks.

Library authoring without a supplied probe remains a declaration-only path.
The ordinary CLI supplies the shared availability probe by default, including
dry-run review. A saved review keeps its selected cycle when reloaded; later
publication changes cannot silently substitute another background.

A named table-route fetch validates its existing request and every cached
object under the download lock before deciding which objects need transfer.
An intact local inventory remains usable after provider retention expires;
only missing or changed objects require network recovery. Native preparation
still checks the resulting composition and scientific input identities.

A prepared bundle is checked by the ordinary portable forecast reader before
it supplies a regional state. That reader verifies the scientific authorities,
cache and actual input inventory. Local handoff review binds the supplied file
bytes; native preparation still verifies their field and time coverage. Neither
catalog recognition nor a declared publication delay proves payload completeness.

The current catalog exposes 18 preparable sources through 13 automatic chains,
three local-input rows and two rows requiring an already prepared bundle. Every
preparable row may also read a portable bundle through the common reader. The
catalog lists each row's actual modes and obligations; these counts are a
snapshot, not the dispatch table.

A source member is verified through its native identity owner. When a table
preparation retained its forcing-member receipt without an embedded member
label, its exact primary-file order and original source bytes are rechecked.
A supplied ensemble analysis whose cache omits membership needs its original
GRIB role, matching the prepared manifest, for the native member check. Provider
selection is a declared acquisition choice; a supplied cache does not establish
an archive origin that its own evidence omits.

Completed preparation is reused only after the ordinary reader verifies it.
An outdated or damaged owned cache before member state exists is preserved and
prepared again in a new owned generation, using the same verified download
cache. Original supplied bundles are never rewritten. If numerical member state
already depends on an incompatible preparation, the old case is retained and a
new reviewed run is required; checkpoint identity is not changed or bypassed.
Older reviews retain their literal configuration and fetch intent, including the
original cycle, and retain the recovered preparation pointer across attempts.

These are finite regional initialization and recovery paths. They do not add a
continuous controller or renew boundaries during a running forecast. CPU and
native contract checks establish software behavior; they do not measure the
forecast skill of every listed source or establish undocumented source units.
