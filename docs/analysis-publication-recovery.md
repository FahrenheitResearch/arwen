# Finite analysis publication

Every member's analysis is staged before any member becomes visible. The
retained `analysis-publication.json` binds the complete ordered roster,
full-file identities, actual background checkpoints, current run and method
identities, positivity and moment policies, and the full prospective method
receipt. `analysis-commit.json` identifies that immutable decision after the
whole set has been published.

A retry verifies every surviving member copy and every recorded input before
finishing any remaining rename. It returns the original receipt and preserves
already published bytes. Losing the outer cycle manifest's DONE write therefore
does not rerun assimilation. The supported roster reader verifies the decision
before returning the complete member set.

The receipt and context must also agree with each other. Their method callable,
declared provenance, positivity and moment policies, and complete member roster
are checked against every available enclosing run binding before either the
cycle runner or the recovering reader can publish. A matching self-digest does
not override a contradictory method, policy or member count. A direct caller
without an enclosing cycle retains its explicit context; no missing authority
is invented for it. That exception requires the enclosing cycle manifest to be
absent. A null or missing context field cannot hide an authority that exists.

The local DA backend freezes observations through its existing observation
owner before binding an analysis. The context includes the review, grid and
analysis time, frozen window and asset identities, prepared proof, configuration
files and end-of-leg surface diagnostics. Recovery requires that original
window and never downloads a replacement for a committed logical analysis.

The callable binding includes its available Python bytecode identity and the
caller's declared method metadata. Arbitrary callable closure state, external
services and native code behind a custom callback cannot be inferred from a
function name. Such inputs belong in the caller's explicit context. The local
backend supplies its concrete input context through the shared cycle seam.

Older completed receipts can still be checked against their recorded member,
state, policy and method facts while preserving the original analysis files.
This does not invent an implementation identity that an older receipt omitted.
An unfinished legacy marker lacks the original method receipt and full-file
identities: it is retained without renaming or recomputing its members. Recovery
requires the original complete receipt or a separate logical run that preserves
the old files.

The existing single-writer contract remains in force; the local launch owns its
run lock. Record creation is exclusive and cannot replace an existing decision.
File contents are flushed before publication; directory durability follows the
platform's filesystem support. No increment arithmetic, positivity rule, moment
repair, forecast clock or observation operator is changed by this protocol.
