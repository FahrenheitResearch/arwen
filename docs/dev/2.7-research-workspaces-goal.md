# ArWen 2.7 research workspaces: release acceptance goal

Status: active development. Public release remains pending the owner's approval.
The qualified 9c727d3c5 build is a retained baseline; its evidence does not qualify the new UI or research configurations.

## Expanded scope accepted 2026-09-06

Build a polished, visually inspected Frutiger Aero / solarpunk terminal workspace that presents research questions, working configurations and actual resource tradeoffs.

- Organize weather families into useful submodes and research subtypes. Severe weather must include distinct hail, derecho, supercell/rotation and related research questions, with comparable specificity in tropical, winter, rain, fire, wind, temperature, aviation, terrain and coastal work.
- Give every final research subtype at least **three distinct, recommended configurations**. Families and submodes must surface recommended starting configurations as well. Each recommendation explains its research question, relevant diagnostics, input requirements, methods and practical limits.
- Provide deliberately chosen options for **8, 12, 16, 24 and 32 GiB** GPU classes. Reuse the actual engine's sizing and resource checks, include measured free memory and headroom, and distinguish resolution, coverage, nest count, output cadence and runtime cost. A card name alone is not a fit guarantee.
- Make small-GPU configurations useful. Evaluate compact nests, archived-parent downscaling, sequential refinement, supported moving domains and tile streaming. Do not promise that arbitrary numbers of refinement stages recreate information absent from the parent or eliminate physics/cadence/corridor constraints.
- Expose supported storm/feature following with appropriate fields and units. Current native trackers support pressure/height, updraft helicity and reflectivity; any additional tracking attribute must be implemented and validated before being offered as working.
- Validate on the owner's available **32, 16 and 10 GiB** hardware. Identify each actual device, driver, operating system, free-memory budget and source revision. State when a recommendation is measured on native hardware, tested under a restricted budget, or still estimated. A restricted-budget test is not evidence from a physical 8/12/24 GiB card.
- Give the Scenario Lab real usable launch paths. Initial-state warm bubbles and experimental perturbation capabilities retain their actual engine constraints. No hurricane insertion, relocation or balanced-state operator is claimed without implementation and evidence.
- Verify configuration creation, preserved user settings, review, preparation, forecasting, diagnostics, checkpoint/resume and moving/downscaled runs as appropriate to each method. Every recommended configuration needs an explicit result in the validation matrix. Failures stay visible and block the affected recommendation.
- Keep all existing CLI, full-TOML, custom plots, Linux Nodes, recovery and installed-package behavior usable. Finish the separately implemented MCP v2 handoff and update its engine-data verification for the final release candidate.
- Produce coherent Windows/Linux artifacts, actual native UI captures, a research configuration catalog, a hardware/method validation matrix, and a concise approval packet. Do not publish, tag or release until the owner approves.

## Implementation and acceptance tracking

The working source now includes the shared solarpunk palette, compact/spacious layouts, 12 families, 23 submodes, 38 final research questions and 114 configurations, five hardware profiles, native attribute following, reviewed warm-bubble editing, an existing-history render guide and actual HTML/JSON terminal-cell captures.

Fresh GFS preparation now accepts the supported warm-bubble domain tree. Full three-hour development forecasts and exact checkpoint restoration have run on real hardware. Cross-platform replay and actual archived-parent inputs exposed additional bounded validation defects, which are being closed and independently tested.

The [qualification record](research-qualification.md) separates all 570 CPU configuration/class rows, physical allocation checks, full forecasts, bounded movement/restart proofs and remaining input or hardware blockers. Its development results do not qualify the final installed artifacts. Public release remains pending the owner's approval after the remaining acceptance work.
