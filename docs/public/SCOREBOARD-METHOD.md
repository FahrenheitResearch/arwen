# Forecast scoreboard method v1

Each completed forecast frame is extracted at every station in a frozen public station inventory and on the registered verification grid. Extraction does not depend on which observations have arrived. A score becomes available when the forecast, baseline and observation exist. New observations create a new score version. Existing versions retain their source hashes and sample support.

## Native data path

`gpuwm scoreboard --request request.json` runs `rw_scoreboard`. Python resolves the executable and forwards requests. NetCDF and GRIB decoding, station matching, interpolation, accumulation, QC, columnar encoding and scoring happen in Rust. GRIB decoding and wind normalization use the existing `rustwx-io` and `grib-core` readers. Neighbour searches use `obs-regrid`. WRF forecast initialization is read from SIMULATION_START_DATE, then START_DATE, or inferred from Times minus XTIME. A supplied initialization must agree with native metadata. An unresolved latest plan can omit initialization; the first native frame supplies immutable initialization and actual lead metadata. A latest run with neither start metadata nor usable XTIME is refused rather than assigned a guessed cycle. Initialization strings are normalized to UTC, and cycle comparisons use timestamps rather than ISO spelling. Exact whole-second leads are derived from valid time minus initialization and returned as lead_seconds; legacy lead_minutes is the truncated compatibility value. Scoring and temporal interpolation retain exact seconds, including a thirty-second frame.

Actions are `plan`, `extract`, `observe`, `merge`, `interpolate`, `accumulate` and `score`. Every action writes a JSON artifact or metric receipt. Extracted weather arrays also receive a compact columnar object with magic `WFSBCOL1`, a little-endian compressed metadata length, a zstd-compressed JSON header and a second zstd frame of little-endian f64 columns. The header contains complete artifact metadata, per-variable observation times, source hashes, diagnostics and missingness. The native reader accepts either JSON or the columnar artifact directly. Missing values in binary columns are NaN. The JSON companion represents missing grid values as null. Forecast artifacts contain point samples and the bounded verification lattice, never history files.

## Spatial interpolation and height

Native latitude and longitude cell quadrilaterals are inverted to fractional coordinates. Longitude differences wrap across the dateline. The field is bilinearly interpolated from four mass-grid corners. A point outside the grid is missing. Every corner must be finite; encoded NetCDF fill and missing values are masked before interpolation. Forecast errors are not screened by their size. The same operator is used for model station sampling and sampling model or MRMS fields onto the common geographic lattice. Reflectivity is converted from dBZ to linear radar power Z before spatial interpolation, then converted back to dBZ. This is applied to both forecast arms and radar.

Terrain is interpolated with the same weights. Both forecast models use:

`T_station = T_raw - 0.0065 * (station_elevation_m - model_terrain_m)`.

The correction is 6.5 K/km. Adjusted temperature and surface pressure are missing when the absolute height difference exceeds 500 m or model terrain is absent. Raw temperature remains available as a separate diagnostic. The correction is a fixed representativeness convention, not an estimate of the actual boundary-layer lapse rate. Dewpoint is not lapse-corrected. Surface pressure is adjusted by `p_station = p_model * exp(-9.80665 * dz / (287.05 * (T_raw - 0.00325 * dz)))` and is a native diagnostic.

WRF dewpoint uses vapour pressure `e = Q2 * PSFC / (0.622 + Q2)` and the Bolton water formula `Td = 273.15 + 243.5 * ln(e/611.2) / (17.67 - ln(e/611.2))`. Q2 is mixing ratio in kg/kg. Baseline native two-metre dewpoint is used when present.

WRF winds are rotated to Earth at each cell using COSALPHA and SINALPHA before station interpolation: east = u*cos - v*sin; north = v*cos + u*sin. A projected field without orientation is missing. Unprojected geographic fields use their Earth-relative components. Operational GRIB scan orientation and grid-relative wind rotation use the existing Rust reader. Wind speed is the magnitude of the interpolated Earth-relative vector.

## Observation admission and time

IEM METAR/ASOS CSV, AWC JSON or its full gzip CSV cache, the existing neutral observation table, public MADIS mesonet NetCDF, German DWD decoded SYNOP GeoJSON and MRMS GRIB are read natively. The frozen inventory comes from all supported rows before valid-time matching, rather than only reports available at the target time. Plans can combine versioned station inventories. Exact station identifiers are retained; the US three-letter/four-letter K-prefix alias requires matching locations within 5 km and maps to the frozen inventory identity.

Surface matching chooses the closest QC-passing report within 600 seconds of the forecast valid time for each variable. Equidistant reports use the earlier time. Same-time conflicts have deterministic input precedence. Each variable retains its observation time and source. A corrected same-time missing or QC-rejected field creates a source-specific retraction. Merging withdraws that source/report/variable value, while a wholly absent report in a partial feed preserves earlier data and another source remains eligible. An unavailable revised cohort withdraws unsupported current scores and aggregates; all earlier score versions remain in history. Surface QC admits temperature and dewpoint in 233.15 to 328.15 K, dewpoint at or below temperature, wind speed in 0 to 75 m/s, and station pressure in 30000 to 110000 Pa. Forecast error magnitude is never a QC criterion. The live IEM fetch explicitly requests report types 1, 3 and 4 through `rw_asos fetch --report-types 1,3,4`: HFMETAR high-frequency reports plus routine and special METARs. Available HFMETAR cadence varies by station; its provider report timestamp is published. This uses the live METAR route, and the existing fetch default remains 3,4. IEM altimeter settings are converted to station pressure with the standard-atmosphere formula used by the existing observation reader.

MADIS permits an explicit unrestricted record flag. Missing restriction flags require an exact provider entry in the frozen category-3 public-distribution table, which includes RAWS. Other restriction flags are excluded. The provider table carries its source URL and version. QC summaries C, S, V, K and G qualify; unchecked and failed summaries do not. Only explicit ten-metre wind fields qualify for the wind comparison. No sensor-height conversion is invented. Source, admitted and excluded provider counts are receipted. [NOAA provider restrictions](https://madis.ncep.noaa.gov/mesonet_providers.shtml).

German DWD decoded SYNOP bulletins are read as gzip GeoJSON FeatureCollections. Numeric data_NNN descriptor order binds each field to its current sensor height: temperature and dewpoint require explicitly reported 2 m height, wind requires 10 m height. Units must be K, m/s, degrees and Pa as appropriate. Null fields and physical QC failures create source-specific retractions. Geometry supplies latitude, longitude and elevation; descriptor date and time supply observation time. A bulletin filename is not a report-time guarantee. Archives retain all report times, and each target uses the same 600-second matching rule. This source is attributed © Deutscher Wetterdienst under https://kunden.dwd.de/ankonda/info/copyright.jsf, and the feed scope is German DWD bulletins. Redistribution of international collections is not inferred from that scope.

MRMS nominal valid times match within 120 seconds. The small offset of a reflectivity composite is retained through source provenance. No-coverage reflectivity values at or below -900 dBZ are missing. No-echo values between that ceiling and -90 dBZ are valid clear observations, mapped to -35 dBZ. Values such as -31.5 dBZ remain valid. Negative QPE is missing. An encoded accumulation duration must match the requested window.

## Accumulation and intermediate frames

WRF precipitation is RAINNC plus RAINC, including encoded bucket counters when BUCKET_MM is positive. Each cumulative endpoint is independently interpolated onto the same frozen station and verification-grid support before subtraction. This also handles a moving child whose native geography changes between endpoints. Newly covered cells without a valid earlier endpoint remain missing; no grid-index subtraction or invented zero is used. A 60-minute or 360-minute amount therefore spans the exact physical interval and location. A decrease greater than 0.0001 mm is a missing reset; a smaller negative difference is clamped to zero. Both endpoint byte hashes and interval times enter provenance. Workers can retain compact cumulative artifacts and use `accumulate` directly rather than reading old history files again.

GRIB APCP is selected by its encoded accumulation duration, not file order. A one-hour message cannot stand in for a six-hour amount. When an encoded interval is absent, cumulative messages starting at the forecast cycle are differenced between exact endpoints. The baseline reference cycle and valid times are checked against GRIB metadata.

For intermediate valid times such as five and fifteen minutes, two hourly baseline extraction artifacts bracket the target. No extrapolation is allowed. Instantaneous temperature, dewpoint, pressure and Earth-relative wind components are interpolated linearly in time. Wind speed is recomputed from the components. Reflectivity is interpolated in linear radar power Z in time, then converted to dBZ. Cumulative precipitation is interpolated at each interval endpoint and then differenced for the exact observation window. These rows are labelled as temporally interpolated baselines, with bracket valid times, weights and source hashes. This permits scoring each forecast frame while making the baseline time approximation explicit.

## Scores and sample support

Each paired score uses the intersection of valid WOOF, observation and baseline samples for the same variable, valid time, accumulation window and frozen geographic support. The service selects the newest available operational cycle at or before the actual WOOF initialization. A newer baseline cycle is refused. An older cycle is accepted only with the explicit `latest_at_or_before_init` policy; native strict mode defaults to the same cycle. Baseline initialization, actual baseline lead and cycle gap in seconds are published. Different cycle-gap groups remain separate in comparisons and aggregates, so a six-hour-old baseline cannot silently appear as a same-cycle forecast. HRRR is the first baseline; GFS supplies a disclosed fallback outside its footprint or forecast horizon. RAP and NAM are optional comparisons using the same cycle rule. Missing stations, terrain exclusions and missing grid cells are counted. Per-variable cohort hashes include selected observation times. Surface metrics are MAE, RMSE and signed mean error. Their sufficient statistics are count, sum of errors, sum of absolute errors and sum of squared errors.

Gridded amount or value bias, MAE and RMSE use the same shared mask and retain their native units, mm or dBZ. Reflectivity value errors include the registered no-echo floor, so quiet-scene dBZ errors are not event-detection skill. Precipitation thresholds are 0.1, 1, 5, 10 and 25 mm. Reflectivity thresholds are 20, 30 and 40 dBZ. Contingency counts yield frequency bias and equitable threat score; CSI, POD and false-alarm ratio are additional native diagnostics. Undefined ratios are null.

Fractions skill score uses nominal square widths of 1, 3, 10, 25 and 50 km. On a geographic lattice, north/south pixel size uses Earth radius 6371008.8 m and latitude spacing. East/west pixel size also includes cos(latitude) for each target row. Each axis chooses its closest odd cell count. Pixel quantization means actual box width varies around the nominal scale; actual north/south width and the east/west width range are reported. Scales finer than the largest pixel dimension are omitted with the reason `below_lattice_resolution`. A coarse lattice therefore cannot claim one-kilometre skill. Grid spacing may be chosen deterministically from the registered region before weather data arrive, and is part of the frozen support hash. Missing cells are excluded from both neighbourhood event fractions, with one shared three-way validity mask. Outside the array contributes no observation. The scoring sum uses valid centre cells. FSS is `1 - sum((forecast_fraction - observed_fraction)^2) / sum(forecast_fraction^2 + observed_fraction^2)`. An all-clear zero denominator is null, with correct-negative counts still shown. It is never a perfect-skill award.

Aggregations pool sufficient statistics on matched cohorts. They retain station and grid sample counts, verified leads and days. Correlated stations, pixels, frames and overlapping forecasts are not independent cases. Wins and losses use the same registered metric and support. Quiet scenes and small samples are displayed as such. Observation-source revisions and method changes create explicit versions. A semantic observation hash excludes unrelated raw feed byte changes, preventing identical regional data from creating spurious score revisions.

## Native request examples

```json
{"action":"observe","format":"iem_csv","input":"observations.csv","valid_time":"2026-10-02T00:00:00Z","stations":"plan.json","grid":{"south":37,"west":-123,"dlat":0.01,"dlon":0.01,"nx":101,"ny":101,"dx_m":1000},"output":"observations.json"}
```

```json
{"action":"extract","format":"wrf","input":"wrfout-current","previous_input":"wrfout-one-hour-earlier","window_minutes":60,"valid_time":"2026-10-02T00:00:00Z","init_time":"2026-10-01T18:00:00Z","lead_minutes":360,"domain":"d02","stations":"plan.json","grid":{"south":37,"west":-123,"dlat":0.01,"dlon":0.01,"nx":101,"ny":101,"dx_m":1000},"output":"forecast.json"}
```

```json
{"action":"score","forecast":"forecast.json","observations":"observations.json","baseline":"baseline.json","variable":"t2","output":"scores.json"}
```

GRIB requests use `format: "grib"`, the Rust registry model name such as `Hrrr`, and `forecast_hour`. For cached intermediate-time baselines, hourly extractions use `include_cumulative: true` and `window_minutes: 0`. `interpolate` accepts `lower`, `upper` and `valid_time`; `accumulate` accepts `current`, `previous` and `window_minutes`. `merge` accepts ordered `inputs`, with the first input winning same-time ties and corrections. Raw `observe` requests can add `archive_output` to retain every normalized report time and retraction candidate in a compressed `WFSBOBS1` archive. Decode with an empty or complete source inventory, then `observe` with `format: "archive"` projects that cache onto each frozen plan without decoding the raw feed again. The receipt includes archive path, byte count, digest and report count. `plan` accepts `stations` or `station_inventories`, `bbox: [west,south,east,north]`, optional `grid`, and `output`.

## Reused verification evidence

The station bilinear operator, deterministic closest-time matching, common-support discipline, masked neighbourhood fractions and contingency formulas come from `gpuwm/verify/obs/stations.py`, `fss.py` and `contingency.py`. MRMS no-echo and no-coverage semantics are the existing `rw_mrms` reader's registered rules. The earlier IFS versus operational-model experiment and its observation dossier informed accumulation-window checks, paired station support and adverse-result reporting. V1 removes that experiment's forecast-error-dependent station exclusion and latitude-independent neighbourhood widths. It does not import its case configuration or historical skill claims.
