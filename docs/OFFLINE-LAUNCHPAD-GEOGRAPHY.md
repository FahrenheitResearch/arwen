# Offline launchpad geography

The launchpad includes display geography and a searchable global place catalog. Neither is input to initialization, WPS static fields, forcing, or the numerical forecast. Selecting a search result changes only the requested latitude and longitude; the existing domain wizard still constructs the configured projected grid. Exact coordinates, panning, and all other forecast controls remain available.

The region preview is an approximate geographic rectangle. After draft creation, the map draws the actual projected cell edges reported by the shared configuration inspector. Place labels and simplified map boundaries are orientation aids, not observations or weather echoes.

## Coverage and attribution

Natural Earth public-domain 1:10 million land, lakes, country boundaries, and state/province lines come from the existing repository assets. Display paths use a 0.0025-degree simplification tolerance, with coordinates rounded to 0.001 SVG units. This does not modify the scientific WPS geography. Boundary depictions follow the upstream dataset.

The place catalog is derived from [GeoNames](https://www.geonames.org/), specifically the [cities15000 extract](https://download.geonames.org/export/dump/cities15000.zip), joined to `admin1CodesASCII.txt` and `countryInfo.txt`. The source is licensed under [Creative Commons Attribution 4.0](https://creativecommons.org/licenses/by/4.0/). The bundled extract, downloaded 2026-09-05, contains 34,136 populated places, mainly cities with populations above 15,000 and capitals. It does not include every village, address, or local name.

Names, alternate names, region/country labels, coordinates, IDs, and population ranks are selected from GeoNames. Source coordinates are retained. Population only orders otherwise equally matching search results and declutters visible labels; the interface does not present it as a current demographic measurement. Attribution and license links are available through the map's local **map sources** link.

Search uses local/ASCII/alternate names and region/country terms. Typing alone never moves the center. Ambiguous matches show their region, country, and exact coordinates; the user selects one. No-match results preserve manual coordinates and panning. A missing/unreadable catalog leaves the overview map and manual entry available.

## Rebuild the asset

`tools/arwen-launchpad/web/geography-manifest.json` records source and output SHA256s. The upstream download endpoints are rolling datasets: verify the recorded hashes when reproducing this exact edition. A newer upstream edition is a deliberate asset update, not an automatic startup action.

After obtaining the named GeoNames files, extract only `cities15000.txt` from the ZIP into a source directory. The Rust builder uses only the crate's existing dependencies:

```text
cd tools/arwen-launchpad
cargo run --release --locked --offline --bin build-geography -- ../rustwx/assets/basemap GEONAMES_SOURCE_DIR OUTPUT_JSON
```

Package `OUTPUT_JSON` with standard-library `gzip.compress(data, mtime=0)` into `tools/arwen-launchpad/web/geography.json.gz`, then verify both output hashes against the manifest. Geographic parsing and transformation are implemented in Rust; gzip is packaging only. Python 3.13.7 was used for this edition's deterministic gzip. The committed compressed asset is 7,315,732 bytes; it decodes to 18,833,827 JSON bytes. No new crate, online map service, telemetry, geolocation request, or runtime download is required.

The JSON stores land/lake/country/province display paths and rows described by `place_columns`. The server embeds its gzip bytes and supplies the matching content encoding. The browser paints map geometry once per map element and declutters up to 30 visible labels; search considers the full catalog and displays up to 12 matches at a time. These display limits never restrict valid coordinates or forecast configurations.

## Verification

The Rust builder checks SHP structure and finite longitude/latitude values, and rejects malformed place coordinates. Its direct tests cover retained bends/endpoints and closed rings. The same pinned source files generated byte-identical JSON on Windows and Linux.

Browser validation should exercise a country-interior region, a coastline/province region, non-ASCII aliases, ambiguous/no-match queries, keyboard selection, exact manual coordinates, panning, and viewport resize. An independent raw GeoNames record should anchor each selected coordinate, and actual draft creation plus the real `go --dry-run` door should retain that center and all unrelated controls. This is a planner/interaction check; a forecast remains a separate explicit action.
