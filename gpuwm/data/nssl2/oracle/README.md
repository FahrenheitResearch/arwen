The harness compiles the exact byte-pinned NSSL module and changes only the
Fortran accessibility of its private numerical routines.  The CSV files
contain direct routine outputs and the adjacent public-driver clamps.  The
initial-state fixture records inputs and outputs from WRF's exact
`calcnfromq` routine.  The self-collection fixture isolates warm rain in the
exact `nssl_2mom_gs` process routine.  The autoconversion fixture begins with
no rain, excluding accretion and self-collection by construction.  No
executable WRF statement is patched.  The accretion oracle uses the module's
own namelist switches to disable neighboring warm-rain processes while
leaving its default accretion branches unchanged.
The evaporation oracle uses the same native switches with only warm rain and
subsaturated vapor populated, excluding all neighboring process rates.
The activation oracle begins with no hydrometeors, so it isolates the native
two-pass saturation adjustment, Twomey activation, predicted-CCN coupling,
droplet bounds, and cloud-free CCN restoration.  The cloudy-water oracle
begins with cloud droplets but no rain or frozen hydrometeors, isolating
analytic full/partial evaporation, adaptive RK2 weak-supersaturation
condensation, predicted-CCN restoration, and droplet bounds.  Neither fixture
is an oracle for rain condensation or frozen NUCOND branches.  The separate
cloud-interior-renucleation oracle begins with cloud water above the
0.5-percent gate and isolates adaptive condensation plus default `irenuc=2`
Twomey/Cohard-Pinty activation, predicted-CCN depletion, vertical gates, the
half-condensed-mass cap, and final droplet bounds.  It stops below the separate
1.9 vapor/saturation-ratio QVEXCESS branch.
The snow fixture disables neighboring nucleation and fragmentation and starts
with snow alone.  The ice-deposition fixture starts without snow, rain, cloud
water, graupel, or hail and disables primary ice nucleation and snow
fragmentation.  Its positive ice supersaturation therefore exercises WRF's
native column-ice capacitance/ventilation, two-pass deposition limit, and
100-micron depositional ice-to-snow conversion without adjacent cold-process
rates.
The coupled frozen-vapor fixture additionally populates ice, snow, or both
and spans deposition, sublimation, near-saturation, and limiter-controlled
states.  Its dynamic saturation-table temperature is constructed using the
same separately rounded multiply and add operations as the official Fortran;
allowing CUDA to contract those operations changes a table index near a
half-step boundary.
The graupel/hail fixture extends the same signed vapor-exchange isolation to
both dense frozen categories and records their predicted volume moments.  The
Bigg fixture instead holds vapor at liquid saturation, empties every adjacent
hydrometeor category, and disables optional snow/splinter routing, so only
default option-2 rain-tail freezing into graupel remains active.
The rain--ice fixture holds vapor at liquid saturation and disables Bigg
freezing, self-collection, nucleation, deposition, snow routing, and
splinters.  Its warm coexistence row deliberately admits the unmodified
official source's misplaced-`ENDIF` fallback rather than silently correcting
or filtering it.
The secondary-ice fixture runs the official driver eight times: one true-off
baseline, six single-family modes, and one all-target mode.  The canonical
fixture is the all-target output with the baseline tendency subtracted; the
family-isolated output is generated as an additional diagnostic.  The
baseline uses `ibfc=3`, `icfn=0`, `itype2=0`, `iglcnvi=0`, `iglcnvs=0`, and
post-namelist `ihlcnh=-1`.  This matters because `ibfc=0` admits WRF's
alternate cloud-freezing path for `ipconc=5`, while `ihlcnh=0` selects its
legacy wet-growth conversion.  Every generated namelist is audited against
the source declaration, failing on any unknown token.
The graupel-sedimentation fixture spans four timesteps, sharp/sparse/smooth
columns, below-minimum and above-maximum input diameters, zero-number positive
mass states, and five predicted particle densities. It calls WRF's unmodified
`sediment1d` with only graupel populated and records all three prognostic
moments plus surface mass export.
The hail-sedimentation fixture uses the same four timesteps and six column
families while independently spanning 500--900-kg/m3 particle density,
below-minimum/above-maximum hail diameters, and zero-number positive-mass
states. It records hail mass, number, predicted volume, and surface export.
The low-mass column is an explicit guard for the initialized two-moment
graupel threshold of `1e-12`. An initial CUDA candidate incorrectly retained
the pre-number-moment `1e-7` threshold and failed 10 of 72 graupel-mass cells
(maximum absolute error `4.958345e-9`, relative error `0.5296206`) because it
suppressed fallout through the `1e-11`--`1e-8` layers. The admitted kernel
uses the post-initialization threshold and passes that causal case.
