## Parameter identity

The harness feeds the WRF table readers this repository's byte-pinned assets
(`gpuwm/data/noahmp/MPTABLE.TBL`, `SOILPARM.TBL`, `GENPARM.TBL`), not the WRF
checkout's `run/` copies: `build.sh` copies them into the build directory,
re-verifies their SHA-256 there, and the readers open them by name from the
working directory. The oracle and `gpuwm/core/noahmp.py` therefore parse
identical bytes.

The reader call order is exactly `module_sf_noahmpdrv.F` `NOAHMP_INIT` lines
2000-2007 under the pinned identity, which has `iopt_irr = 0` and so never
calls `read_mp_irrigation_parameters`.

| Case | vegtype | soiltype | slopetype | soilcolor | Regime |
|---|---:|---:|---:|---:|---|
| `evergreen_needleleaf` | 1 | 6 (loam) | 1 | 4 | woody canopy, mid-range hydraulics |
| `grassland` | 10 | 3 (sandy loam) | 2 | 4 | herbaceous canopy, permeable soil |
| `cropland` | 12 | 8 (silty clay loam) | 1 | 4 | `ISCROP` category with `croptype = 0` |

Branches proven by `validate_parameters_oracle.py`: the MODIS category

from MPTABLE but never transferred), and `FRZX` for `soiltype = 14`, which is
why no case uses that soil category.

### Achieved gpuwm parity

`gpuwm.core.noahmp.transfer_mp_parameters` transcribes
`module_sf_noahmpdrv.F` lines 1435-1710 for the non-crop, non-irrigation
branch, reading the same byte-pinned tables through
`gpuwm.core.noahmp.load_noahmp_parameters`. `tests/test_noahmp_oracle.py`
drives it over all seven identities and compares against this fixture in
WRF's own working precision (IEEE binary32):

| Class | field/index pairs per case | Parity |
|---|---:|---|
| direct table lookups | 162 | exact equality, `max_ulp = 0` |
| `URBAN_FLAG` overrides (`SMCMAX`/`SMCREF`/`SMCWLT`/`SMCDRY` x 4 layers, `CSOIL`) | 17 | exact equality, `max_ulp = 0` |
| derived (`KDT`, `FRZX`) | 2 | exact equality, `max_ulp = 0` |
| **total** | **181** | **1,267 / 1,267 values bitwise identical** |

`max_ulp = 0` holds for every field on every case; no tolerance is applied
anywhere. The comparison is bitwise in binary32 because the fixture's `g0`
output is a 9-significant-digit, round-tripping form of WRF's default `REAL`.
Comparing in binary64 instead reports 682 of the 1,267 values as different --
that difference is the binary32-vs-binary64 rounding of the same table bytes,
not a disagreement.

The derived pair is checked twice: once against gpuwm's transfer, and once by
re-deriving it from the fixture's own `REFKDT`/`DKSAT(1)`/`REFDK` and
`SMCMAX(1)`/`SMCREF(1)` columns in binary32, so the expression
`KDT = REFKDT*DKSAT(1)/REFDK` and
`FRZX = FRZK*(SMCMAX(1)/SMCREF(1))*(0.412/0.468)` is pinned independently of
the port. The urban case additionally proves the override precedes `FRZX`, so
its `FRZX` is formed from `0.45/0.42`, not from the loam entry.

Nothing is skipped: the test partitions the 181 pairs into the three classes
above and asserts the partition is exhaustive and disjoint. The components
that remain **outside** oracle validation are asserted to be absent from both
the fixture and the port, so the gap fails loudly if it is ever half-closed:

- the crop branch (`PLTDAY`..`BIO2LAI`, 41 components, plus the crop
  overwrites of `C3PSN`/`KC25`/`AKC`/`KO25`/`AKO`/`AVCMX`/`VCMX25`/`BP`/`MP`/
  `FOLNMX`/`QE25`) -- `transfer_mp_parameters` raises `NotImplementedError`
  for `croptype > 0` rather than approximating it;
- the irrigation block (`IRR_FRAC`, `IRR_HAR`, `IRR_LAI`, `IRR_MAD`,
  `FILOSS`, `SPRIR_RATE`, `MICIR_RATE`, `FIRTFAC`, `IR_RAIN`) -- WRF never
  assigns these under `iopt_irr = 0`;
- `SLAREA`, `EPS1`..`EPS5` -- read from MPTABLE, never transferred;
- `FRZX` for `soiltype = 14`, which the port omits from its output mapping
  exactly as WRF leaves the component unset. `SOILPARM.TBL` row 14 has
  `REFSMC = 0`, so the guarded expression would divide by zero.

## `noahmp-sflx.csv`

- 55,544 bytes; 1,216 data rows;
- SHA-256 `76abe0d9e7ab69c3359c1cd641422ef776fcead777edee0daaf3d6d8dbffcd24`.

Columns `case,stage,field,index,value` with `stage` in `{input, output}`. Each
case's `input` rows are its complete entry state -- forcing, configuration,
every prognostic array (`stc`, `zsnso`, `snice`, `snliq`, `ficeold`, `smc`,
`sh2o`, `smceq`) over the full `-NSNOW+1 : NSOIL` index range, and the soil
parameters this identity consults -- so each column is reproducible from the
file alone. The `output` rows are every `INTENT(OUT)` and every `INTENT(INOUT)`
argument as it leaves `NOAHMP_SFLX`.

The snow-layer state is built by WRF's own `module_sf_noahmpdrv::SNOW_INIT`,
so the layer count, thicknesses and `ZSNSO` convention are WRF's, not the
harness author's.

| Case | Regime |
|---|---|
| `veg_warm_day_dry` | grassland, sunlit (`cosz = 0.82`, 820 W/m2), snow-free, unsaturated soil, transpiring Ball-Berry canopy |
| `veg_warm_night_rain` | same canopy, `cosz = 0` (night-albedo sentinel), 1.2e-3 mm/s non-convective rain, canopy interception + drip + throughfall, `OPT_RUN=3` surface runoff |
| `snowpack_frozen_soil` | evergreen needleleaf, two-layer 0.20 m / 50 mm pack (`ISNOW = -2`), 263 K forcing, snowing (`FPICE = 1`), `OPT_FRZ=1` supercooled liquid in the top soil layer, `OPT_ALB=2` CLASS snow albedo |
| `bare_thin_snow_melt` | barren (`FVEG = 0`), 5 mm / 0.02 m sub-layer snow at 274.5 K -- the `ISNOW = 0, SNEQV > 0` melt path, producing `QMELT > 0` and `PONDING` equal to the mass lost |

`validate_sflx_oracle.py` re-derives WRF's own shortwave residual
`SWDOWN - (FSA + FSR)` and energy residual
`SAV + SAG - (FIRA + FSH + FCEV + FGEV + FCTR + SSOIL + CANHS) + PAH`, both to
better than 0.01 W/m2; checks `RAIN + SNOW` against the forcing precipitation
and the canopy rain partition `QINTR + QDRIPR + QTHROR`; checks the melt-mass
/ ponding identity; asserts `DVEG=4` leaves the carbon pools and `NEE/GPP/NPP`
inert; and asserts each regime's discriminating branch.

## What these vectors do not admit

They authorise comparisons against the WRF Noah-MP parameter transfer and
against `NOAHMP_SFLX` for these four columns only. They do not admit
`sf_surface_physics = 4`: there is no gpuwm Noah-MP column solver yet, so no
parity number exists. They do not cover the glacier column (`ICE /= 0`,
`NOAHMP_GLACIER`), lake columns (`IST = 2`), crops, irrigation, tile drainage,
groundwater/lateral flow, the urban coupling, multi-step accumulation
(`soiltstep > 0`), or any non-default option value.

Every leaf routine of `MODULE_SF_NOAHMPLSM` (`THERMOPROP`, `CSNOW`, `TDFCND`,
`PHASECHANGE`, `FRH2O`, `ESAT`, `TSNOSOI`, `SOILWATER`, ...) carries an
explicit `private ::` accessibility statement at `module_sf_noahmplsm.F` lines
26-84; `NOAHMP_SFLX` and `noahmp_options` are the module's only public
procedures. Per-leaf oracles are therefore not reachable from a program that
compiles the pinned source unmodified, and this fixture pins the whole column
instead.

## `noahmp-driver.csv` — the driver-side cold start

`module_sf_noahmpdrv::SNOW_INIT` (2340-2440) and
`module_sf_noahmpdrv::NOAHMP_INIT` (1828-2335), built by
`tools/noahmp_wrf461_oracle/build_driver.sh` against the **byte-unmodified**
driver and the **pristine** `module_sf_noahmplsm.F`. No visibility patch is
involved anywhere in this fixture's build, and none is needed:
`phys/module_sf_noahmpdrv.F` carries no accessibility statement at all, so
Fortran's default makes every module procedure public. `build_driver.sh`
stage `[2]` asserts that (`grep -c '^ *private'` and `'^ *public'` are both 0)
instead of assuming it, and stage `[3]` refuses to build if the LSM module
carries the leaf-visibility lift — the patched module physically cannot
compile against this driver.

54 cases, 7 790 rows, entry and exit state for every case. All three build
controls — `-ffp-contract=off`, `-finit-real=snan`, and WRF's own
`-O2 -ftree-vectorize -funroll-loops` — reproduce it byte for byte, so unlike
the soil-water fixture there is no recorded `-O2` divergence: `objdump -dr`
places every libmvec reference in the compiled driver inside
`PEDOTRANSFER_SR2006`, which `opt_soil=1` kills and which neither pinned
routine can reach.

Full build flags, branch tally, coverage argument, mutation-study result and
the list of what the fixture does not admit are in
[`PROVENANCE-driver.md`](PROVENANCE-driver.md).

### Why the fixture is trusted

Three independent gates, all executable:

1. **Zero-probe sweep** (`noahmp-leaves-discrimination.csv`, Fortran side):
   for every case and input slot, how many live outputs move when that slot is
   zeroed in the *oracle*. Evidence about what the pinned Fortran reads.
2. **Argument-mutation study** (`gpuwm/core/noahmp_leaf_mutation.py`, port
   side): for every input slot -- FP32 and integer topology alike -- neither
   zero nor any constant the fixture gives that slot may be substituted and
   still reproduce the fixture. 995 mutants across the eight leaves, all
   killed except the declared inert and partially-observable arguments, each
   of which carries the WRF line numbers that justify it. This is the gate
   that catches the defect a sibling lane found: `max_ulp 0` on 29 columns
   with 13 of 14 argument-drop mutants surviving.
3. **Branch coverage** asserted from the *inputs*, not the outputs, so it
   cannot be satisfied by a coincidence: every `OPT_SNF=1` FPICE branch, both
   `IST==2` lake branches as whole columns plus a mixed column, the
   `urban_flag` override and its re-blend, the `SNICEV` saturation clamp,
   every `TDFCND` Kersten branch, and the `WDFCND2` `SICE>0` weighting.

### glibc transcendental identity

`glibc-libm-fp32.csv` (30,000 rows, produced by `dump_libm_reference.c`) pins
glibc 2.39's `logf`, `log10f`, `expf` and `powf` on the oracle host. It exists
because **none of the four is correctly rounded**, so the usual
evaluate-in-FP64-and-round-once shim is the wrong function, not merely a
slower one:

| call | domain | disagreement with FP64-then-round |
|---|---|---:|
| `log10f` | every FP32 in (0.1, 1.0] | 5,266,896 / 28,521,268 = **18.47%** |
| `expf` | FP32 grid over abs(x) <= 25 | 21,750 / 34,902,602 = 0.062% |
| `powf` | 4e6 samples over Noah-MP shapes | 2,618 / 4,000,000 = 0.065% |

(0.1, 1.0] is exactly `TDFCND`'s `LOG10(SATRATIO)` domain, so roughly one soil
column in five would miss `max_ulp 0`. `gpuwm/core/noahmp_libm.py` and the
`r_log`/`r_log10`/`r_exp`/`r_pow` block of `noahmp_leaves.cu` are direct
transcriptions of glibc 2.39 `sysdeps/ieee754/flt-32`, verified against the
live library over 222,414,918 FP32 inputs for `logf`/`log10f` (0 mismatches),
6,000,000 samples for `powf` (0), and 146,800,642 for `expf` (**2**, both 1
ULP: `x = 0x4202422F` and `x = 0xC27C65D9`; residual rate 1.4e-8, a 4,400x
improvement on the FP64 shim, and unchanged by enabling FMA contraction, so
not a contraction artefact). A Noah-MP column landing on either of those two
exact FP32 arguments must be reported, not absorbed.

### The discrimination sweep is a *substitution* sweep here

`SFCDIF1`'s `ZLVL` cannot be probed with 0.0 â€” that satisfies `ZLVL <= ZPD` and
takes the run down. `run_fluxprep.F90` therefore accepts a per-slot probe
vector and the discrimination CSV carries a `probe_bits` column, so no
substitution is implicit. `ZLVL` is probed with 3.0 m; every other slot of
every leaf is still probed with 0.0, and a test asserts that.

### Iteration counts the pinned identity produces

`SFCDIF1` and `RAGRB` run with `ITER = 1..NITERC = 20` in VEGE_FLUX (:3792,
:3877) and `ITER = 1..NITERB = 5` in BARE_FLUX (:4329, :4351); both bodies test
only `ITER == 1` versus `ITER > 1`, so the fixture's `ITER = 1..5` spans the
whole behavioural range. `STOMATA` is called only at `ITER == 1` (:3934) and
runs exactly `NITER = 3` Ball-Berry sweeps (`DATA NITER /3/`, :5045) â€” a
compile-time constant, not a convergence test.

### Two lowering facts this fixture pins

**`atanf`.** `SFCDIF1` (:4691, :4698) is Noah-MP's only `ATAN` caller and
`noahmp_libm` did not carry it. glibc 2.39's `atanf` is the fdlibm reduction
evaluated entirely in FP32, so the FP64-then-round shim is again a *different*
function: it disagrees on 823,767 of the 16,777,216 FP32 inputs in [0.5, 1)
alone. The transcription in `gpuwm/core/noahmp_libm.py` was checked against the
live glibc over **all 4,278,190,082 non-NaN FP32 inputs â€” the entire domain â€”
with 0 mismatches**, after measuring that glibc's large-argument shortcut fires
at 2^25 (`0x4C000000`) rather than the 2^26 or 2^34 thresholds other fdlibm
descendants use. `glibc-atanf-fp32.csv` (4,256 rows,
`c52ad0e0f9f4b43e695210190a5202d064630817aab3bf8a94cde94b17e85e82`, produced by
`dump_atanf_reference.c`) pins a sample so the port-side test needs no live
libm, and a negative control asserts that sample still separates glibc from the
FP64 shim.

**`FV**3`.** gfortran routes a *real* constant exponent through `powf` but an
*integer* one through libgcc's `__powisf2`, which is binary exponentiation:
`fl(x * fl(x*x))`, two roundings, not `powf(x, 3.0)`'s one. The two disagree on
about 26% of FP32 friction velocities. The fixture originally could not see the
difference â€” every case that reached `FV**3` either clamped `MOZ`/`MOZG` to 1.0
immediately afterwards, destroying the 1-ULP difference in the Obukhov length,
or carried an `FV` where the two agree. That was found by a negative control on
the CUDA half, not by inspection. Four `FV` values now sit on the separating
set (RAGRB 0.4196 and 0.5497, SFCDIF1 0.3499 and 0.1999, all in `ITER > 1`
cases whose `MOZ` is unclamped) and the control is a permanent test.

### A leaf fixture pins a function, not a call site

MPTABLE.TBL ships one value of `DLEAF`, `C3PSN`, `AKC`, `AKO`, `AVCMX`, `KC25`
and `KO25` for all 20 MODIS classes, and both `SFCDIF1` call sites pass
`MPE = 1.E-6`. A table-faithful fixture would leave those arguments frozen and
no mutant could be caught hard-coding them, so they vary across cases; each
choice is called out in the per-leaf header of `run_fluxprep.F90`. The same
reasoning puts `C3PSN = 0` in one STOMATA case: the C4 terms are unreachable
through the pinned table but they are arithmetic in one expression, not a
branch behind an option switch.

Three STOMATA cases are explicit domain-corner probes rather than forcing
states, and are labelled as such: `co2_starved_fine` and `co2_starved_coarse`
(CO2 near 0.5 Pa with a reduced O2, the only way to drive `CS` onto the `MPE`
floor at 5118 and take the `B >= 0` root branch at 5121) and
`fveg_clamp_folnmx_zero` (`FVEG = 1e-7`, `FOLNMX = 0`). `SFCDIF1`'s
`degenerate_guards` (Z0M = Z0H = 4e6 m) is likewise the only way to bind all
four `ABS(..) <= MPE` guards at 4729-4732 at once.
