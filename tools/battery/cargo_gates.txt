# The Rust workspaces' test suites, as the battery invokes them.
#
# WHAT THIS IS
#   This tree carries Cargo workspaces that are not decoration: the
#   vendored Rusty Weather renderer under tools/rustwx (every product PNG
#   a run publishes comes out of rw_wrfbatch), the GRIB decoder under
#   tools/grib1_bridge (every byte of GFS and HRRR the model initialises
#   from comes through it), and the mapped decode engine under
#   tools/rw_wps (every mapped source decodes in it by default).  All
#   ship in the release.  None of them had a leg
#   on the release battery: `pytest` cannot collect a Rust test, so the
#   whole of it was invisible to every gate a cut runs, and the only
#   thing the battery ever asked of these workspaces was that the
#   renderer BINARY existed.
#
#   Drew's ruling, 2026-08-12 ("probably we would want tests right"),
#   makes the Rust crate tests a battery leg.  This file is that leg's
#   list, and it is a CURATED ENUMERATION for the same reason
#   tools/battery/stage1_files.txt is: a gate nobody can enumerate is a
#   gate that quietly stops being run.
#
# WHY NOT `cargo test --workspace`
#   One invocation would be faster and would report ONE number.  A crate
#   that stops being a workspace member disappears from that number
#   without changing it in any way a reader can see, and the count moves
#   for legitimate reasons on every commit, so nothing can be pinned to
#   it.  Per-package entries make the membership explicit, give the
#   manifest gate something to compare the workspace against, and let
#   each package carry its own floor.
#
# FORMAT
#   One entry per line, four fixed columns then zero or more trailing
#   tokens:
#
#       SHARD  WORKSPACE  PACKAGE  MIN_TESTS  [KEY=VALUE...] [cargo args]
#
#   SHARD      `cpu`       no card, runnable in the stage-1 environment.
#                          This is the release battery's leg.
#              `gpu`       needs a card.  Nothing is on it today --
#                          neither workspace touches CUDA -- and the
#                          column exists so a crate that grows a
#                          card-dependent test has somewhere to go other
#                          than off the list.
#              `fixtures`  needs a data set the repository does not
#                          carry, fetched from a public bucket by a
#                          script in the crate.  NOT part of the default
#                          leg, listed anyway: see the rw-sat entry.
#   WORKSPACE  repository-relative directory holding Cargo.toml AND
#              .cargo/config.toml.  The config is not optional -- it is
#              the vendored source replacement that makes --offline work.
#   PACKAGE    a member package of that workspace, by name.
#   MIN_TESTS  the expected-green contract: the entry passes when cargo
#              exits 0, reports zero failures, AND runs at least this
#              many tests.  A floor rather than an equality so adding a
#              test does not turn the leg red; a floor rather than
#              nothing because "0 passed" also exits 0, and a feature
#              flag or a `#[cfg]` that stops COMPILING a test module is
#              indistinguishable from a green run without it.  The
#              numbers below are what each package reported on its first
#              green run, 2026-08-12, cargo 1.94.0 on Windows.
#   KEY=VALUE  extra environment for that entry, same idiom and same
#              reason as tools/battery/tiles_gates.txt: an invocation
#              whose real acceptance needs a variable that lives in
#              somebody's shell history is an invocation that drifts.
#   cargo args any trailing token that is not KEY=VALUE is passed to
#              cargo verbatim, after `test --locked --offline -p NAME`.
#              This is how a package splits across shards by TARGET --
#              one entry taking `--lib`, another taking `--test <name>`.
#
#   Blank lines and lines whose first non-space character is `#` are
#   ignored.  tools/battery/run_cargo_gates.py is the runner; it prints a
#   matrix and one verdict line and its exit status is the verdict.
#
# CARGO_TARGET_DIR IS MANDATORY AND MUST BE OUTSIDE THE TREE
#   The runner REFUSES to start without it and refuses one that resolves
#   inside the repository.  This is not tidiness.  A release cut checks
#   the worktree-local renderer at tools/rustwx/target/release and hashes
#   it before it believes any leg that renders; a test leg sharing that
#   directory can rebuild, replace or lock the binary the cut is
#   adjudicating, and the two answers would then depend on which leg ran
#   last.  The gate also stays honest about the tree: a cut refuses to
#   assemble from a dirty source tree, and target/ artefacts are exactly
#   what makes one dirty on a clone whose .gitignore has moved.
#
# OFFLINE ONLY
#   Every invocation is `cargo test --locked --offline`.  Both workspaces
#   vendor their dependencies (tools/rustwx/vendor/crates-io,
#   tools/grib1_bridge/vendor/crates-io) with a .cargo/config.toml that
#   replaces the crates.io source, so a green leg proves the vendored
#   closure is complete.  Dropping --offline would let a leg pass on a
#   box with a warm registry cache and fail on the release box, which is
#   the same class of failure as a gate that lives in a shell history.
#
# AMENDMENT DISCIPLINE
#   Same as stage1_files.txt and tiles_gates.txt: an addition carries its
#   REASON inline, on the lines above it, naming what the package covers.
#   tests/test_cargo_gate_manifest.py is the gate on this file, and it
#   checks BOTH directions -- every entry names a real workspace member,
#   and every workspace member has an entry.  That second direction is
#   how a crate that lands later joins this leg: adding it to
#   tools/rustwx/Cargo.toml's members turns the manifest gate RED until
#   somebody writes its line here, so a new crate cannot arrive already
#   ungated.  MIN_TESTS for a new entry is the count its first green run
#   reported; the runner prints that number.

# ---------------------------------------------------------- tools/rustwx
# The vendored Rusty Weather renderer workspace (VENDOR.md).  Drew's own
# crates, carried at the state that produced the campaign renderer, plus
# rw-wrfbatch, which is this project's.  Every product plot the model
# publishes is drawn by this workspace, and a release ships its binary.

# The NetCDF WRITER (classic CDF-1/2/5), the first write capability in a
# workspace that until now only read NetCDF.  Dependency-free on the
# default feature; its cdylib is the ctypes seam
# gpuwm/io/nc_writer_bridge.py loads, so a regression here corrupts
# every byte a Rust-written wrfout carries.  The round-trip suite reads
# its own output back through an INDEPENDENT reader (netcdf-reader),
# so a shared misreading of the spec cannot make a broken file look
# correct.  Floor is its first green run on the merged 2.5.0 tree:
# 12 lib + 19 round-trip + 1 doctest.
cpu  tools/rustwx  netcdf-writer  32

# The observation battery's REMAP.  `gpuwm/verify/obs/regrid.py` puts a
# scattered observation swath and a model field on one grid, and every
# score the battery reports is read off the result, so a wrong neighbour
# or an unenforced distance bound does not crash -- it grades an arm
# against the wrong cells and reports a number.  The suite is the
# bitwise parity against goldens extracted from the real scipy/numpy
# path (crates/obs-regrid/golden, tests/parity.rs), plus the
# lowest-index-wins tie rule that is this crate's one documented
# divergence from scipy.  Floor is its first green run in this list,
# 2026-08-18: 23 lib + 4 parity; raised to 29 when the two structural
# tests landed (the root bounding box, and the box distance the pruning
# is decided on), because the parity suite compares only ANSWERS and the
# answers do not change when the tree stops being a tree.
cpu  tools/rustwx  obs-regrid  29

# The verification instruments: `rw_fieldcmp`, the paired-FRAME judge
# that prints the campaign metric table, and `rw_runscore`, the
# paired-RUN judge that reduces two run directories to one distance per
# registered metric.  Gated as arithmetic, not as tooling: these are the
# programs a campaign's accept/reject verdict is read off, and their
# whole design claim is that they reproduce the reference judge's bits
# rather than merely being defensible.  The summation contract is the
# load-bearing part -- the pairwise tree, the 8192-element reduction
# buffer around it, and the cell-first ring packing -- and it is what
# these tests pin.  Floor is this package's first green run, 43 across
# the lib, `runscore_contract` and `table_contract`.
cpu  tools/rustwx  rw-fieldcmp  43

# NEXRAD Level II: the radar decoder the DA lane reads its observations

# NetCDF: THE decoder for every NetCDF source the product accepts, since
# that decode moved off the netCDF4 C library and onto the vendored
# netcrust reader.  There is deliberately no Python decoder behind it, so
# this gate is the only thing standing between a broken CF time parse and
# a wrong initial condition -- and its unit tests are the CF
# reference-time cases (the unit spellings, the ISO/Zulu variants, and
# the UTC-offset designators, which convert the epoch to UTC and must
# land on the same instant as the UTC respelling), which is where a
# calendar bug would otherwise reach a forecast.
# Raised from 5 to 7 when `minutes since` and the unpadded `2000-1-1`
# date spelling got tests; both were claimed by the parser and checked
# by nothing.  Raised from 7 to 37 when the mutation debt was worked
# off: the CF unpack order, the dimension-scale recovery, the metadata
# provenance and the argv contract each gained tests (25 lib + 12 in
# tests/cli.rs), and a `#[cfg]` that stopped compiling either binary
# must not leave the leg green.  Raised from 37 to 43 when the held
# non-UTC-offset refusal was replaced by real offset arithmetic (Drew's
# 2026-08-31 ruling): the offset/UTC equivalence, both shift directions,
# the +/-18:00 and 59-minute bounds, the named malformed refusals, and
# the writer-path round trip each pin what the old refusal left silent
# (31 lib + 12 in tests/cli.rs).
cpu  tools/rustwx  rw-netcdf  43

# rw-mpas: THIS project's crate too, and the DEFAULT route from an MPAS
# history frame to a picture -- `rw_mpas_convert` gathers an unstructured
# mesh onto a structured render window and writes the wrfout-shaped
# classic netCDF frame the pinned renderer opens, and `rw_mpas_init`
# builds the mesh side.  It replaced tools/mpas_render_bridge's Python,
# which stays only as the reference the parity record
# (evidence/rw-mpas-converter-parity.json: 127 of 127 PNGs
# byte-identical) is about, so this crate is the only thing between a
# wrong resample weight and an MPAS product plot that is plausible and
# in the wrong place -- a mesh-to-grid gather that picks the wrong cell
# does not crash, it draws the storm somewhere else.  Floor was its
# first green run in this list, 2026-08-20: 61 across the lib.  Raised
# to 399, measured 2026-08-29 across 21 test binaries, because 61 had
# stopped being a gate: the crate's lib binary alone runs 333 tests, so
# a `#[cfg]` that stopped compiling the WHOLE of it -- the exact
# breakage the MIN_TESTS column exists to catch -- would still have left
# 66 passing and the leg green.  A floor that cannot notice the largest
# test binary vanishing is not a floor.  Raised to 418, measured
# 2026-08-30 on the merged mesh-speed tree with the battery's own
# invocation, when the speed lane's gates joined the crate (the
# maintained-triangulation arm, the parallel monitor's tie rule, the
# refusal-by-name doors).
cpu  tools/rustwx  rw-mpas  418

# static-fields: THIS project's crate too, and the DEFAULT builder of
# every WPS-geogrid-equivalent static a domain is built on -- projection
# grids, WPS_GEOG tile ingest, field building, and the high-resolution
# overlay warp.  Its claim is byte-identical float64 parity with the
# Python implementation it replaced, and that claim is exactly the kind
# nothing else in the tree can check: a wrong terrain height or land

# quietly somewhere else.  The suite is that parity, held against
# goldens extracted from the real Python builder on real source data
# (crates/static-fields/golden, tests/lane1_goldens.rs), plus the
# high-resolution warp tolerance parity and the ctypes seam probe the
# cdylib is loaded through.  Floor is its first green run in this list,
# 47 across the lib, `highres_parity`, `lane1_goldens` and `seam_probe`.
cpu  tools/rustwx  static-fields  47

# THE FIXTURE-DEPENDENT HALF OF rw-sat, LISTED AND NOT RUN BY DEFAULT.
# tests/cloud_products.rs decodes four REAL GOES-19 granules -- COD, CPS,
# phase, ACHA cloud-top height -- and checks the CWP computation against
# an independent one.  The granules are ~tens of MB of NetCDF that the
# repository does not carry; crates/rw-sat/tests/fixtures/fetch_fixtures.ps1
# pulls them from NOAA's public bucket.  Without them the suite does not
# skip: it PANICS by name ("fixture dir exists but granule ... is
# missing -- re-run the fetch script"), which is the right behaviour and
# is why `cargo test --workspace` is red on a clean clone of this tree.
#
# It is on its own shard rather than deleted from the list because the
# alternative -- a `cpu  rw-sat` entry restricted to `--lib` and nothing
# saying why -- is how coverage disappears without an argument.  Run it
# where the network is allowed:
#     python tools/battery/run_cargo_gates.py --shard fixtures
# after running the fetch script.  A release cut does NOT block on it.
fixtures  tools/rustwx  rw-sat  4  --test cloud_products

# grib-core: the DECODER ITSELF, vendored at tools/grib1_bridge/vendor
# and a cargo workspace member by the path-dependency rule.  It was
# ungated until 2026-08-16 for a structural reason worth writing down:
# the tree carried TWO copies of it, one per workspace, and neither was
# a listed member of anything, so 8,900 lines that every GRIB byte in
# the product passes through had no leg at all.  The copies are now one,
# this is that one, and its suite is what stands between a
# missing-value-management regression and a field of encoder sentinels
# published as physical data.  Floor was its first green run after the
# convergence, 157 across the lib; raised to 162 when the Section-4 pv
# coordinate octets (the hybrid A/B channel) joined the parse with five
# tests of their own -- a build without them decodes a hybrid source
# into empty coefficient tuples, exactly the L137 proof lane's gap G1.
cpu  tools/grib1_bridge  grib-core  162

# --------------------------------------------------------- tools/rw_wps
# The mapped decode engine workspace: the vendored rw-wps donor snapshot
# (VENDOR.md) plus gpuwm's own crates/mapped-engine.  It joined this list
# the day `gpuwm_mapped_engine` joined the release bundle, which is the
# argument this whole file is built on -- a crate the release SHIPS and

# mapped-engine: THIS project's crate, and the binary every mapped source
# decodes in on a bare run (`gpuwm.mapped_engine_bridge.DEFAULT_ENGINE`
# is `rust`).  Its suite is the decode itself -- selector resolution, the
# level ladder, the acquisition codecs, the frameset writer -- plus the
# goldens extracted from the real Python engine on real published bytes,
# which is the comparison the whole port is judged on.  Floor was its
# first green run in this list, 61 across the lib and `goldens`; raised
# to 114 when the hybrid_sigma_pressure closure landed (pv harvest,
# hybrid pressure, hydrostatic height -- the derivations a hybrid
# initialization is read off); raised to 121 when its CF time parse got
# the same offset arithmetic rw-netcdf got under Drew's 2026-08-31
# ruling -- the offset/UTC equivalence, both shift directions, the
# +/-18:00 and 59-minute bounds, and the named malformed refusals
# replace the retired refuses-rather-than-shifting guard.  The
# goldens target reads the model-gauntlet staging tree when a box has
# one and runs its cases against nothing when it does not, so this entry
# is a compile-and-contract leg on a bare runner and a byte-parity leg on
# a staged one; the Python-side battery
# (tests/test_mapped_engine_parity.py) is where the cross-engine verdict
# is read.
cpu  tools/rw_wps  mapped-engine  121

# rw-wps: the donor mapping/composition/namelist engine this snapshot
# vendors, and the crate the mapped-engine reads its authority files
# through.  Gated for the reason grib-core is: it is vendored, so its
# source does not move with this checkout, but every mapping and
# composition gpuwm ships is parsed by it, and a schema drift here
# reaches a run as a source that silently resolves to different records.
# Floor is the 65 the vendoring recorded green at donor tip (60 lib + 5
# integration), which is also what it reports here.
cpu  tools/rw_wps  rw-wps  65
