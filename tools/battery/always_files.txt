# The battery's ALWAYS list: the gates no selector can find.
#
# WHAT THIS IS
#   The set of test files that run in EVERY lane, unconditionally, however
#   small the change.  They are the repo-scanning gates and the release
#   governance suites: files that read the tree rather than import it.
#
# WHY IT HAS TO EXIST
#   tools/battery/fastfix.py selects tests by DIRECT import edges from the
#   product files a change touched.  That works -- the 2026-08-13 audit
#   validated it against a real defect -- but it is structurally blind to
#   this class, because a citation checker, a line-ending gate or a receipt
#   regenerator has no import edge to anything.  The same audit measured it:
#   commit 6e9c690f0 left tools/ftz_receipt/receipt/route_inventory.json
#   stale, and tests/test_ftz_route_inventory.py is a MISS at import depth
#   0, 1 AND 2.  A selector that skipped it would have shipped exactly the
#   defect the receipt exists to catch.
#
#   So these are never selected.  They are always run.
#
# WHO CONSUMES IT
#   tools/battery/fastfix.py adds every entry here to every selection, and
#   labels the reason "always (repo-scanning gate)".  tools/battery/FASTFIX.md
#   describes the lane.
#
# FORMAT
#   One repository-relative path per line, forward slashes.  Blank lines and
#   lines whose first non-space character is `#` are ignored -- the same
#   parse as tools/battery/stage1_files.txt, and for the same reason: the
#   audit's own membership check reported a path as listed when it occurred
#   only inside a comment.
#
# AMENDMENT DISCIPLINE
#   As stage1_files.txt: an addition carries its REASON inline, on the lines
#   above it, naming the task or the incident that earned it.  A removal is
#   an argument, not a tidy-up.  tests/test_always_manifest.py is the gate --
#   it checks every path exists, rejects duplicates, and pins that a file
#   here reads the tree rather than importing the product, which is the
#   property that makes it unselectable in the first place.

# The standalone RW-WPS wheel's staging boundary, promoted here after it
# burned a SECOND release number (2026-08-14).  It was already a stage-1
# entry, and stage 1 is the wrong depth for it twice over.
#
#   It is blind by construction.  The suite STAGES the wheel by path and
#   AST-walks what it staged; it imports gpuwm.native_wrf_distribution and
#   tools.build_rw_wps_release and nothing else of the product.  So it has
#   no import edge to gpuwm/core/streaming.py -- the file whose imports it
#   actually constrains -- and the selector cannot reach it from the edit
#   that breaks it.  Measured on the 2.3.0 range (v2.2.1..81edc6afa): 87
#   product files touched, streaming.py and nest_stream.py among them, 289
#   tests selected, this suite NOT one of them.  That is the same shape as
#   the receipt-inventory gates above and it belongs in the same list.
#
#   It fails only at a cut, which is the most expensive place to learn.
#   A lane adds a function-local import to a staged module; nothing in the
#   tree objects, because the import is correct everywhere except inside a
#   wheel that omits its target.  Twice now the first objection has come
#   from the publish pipeline with the tag already spent: two imports on
#   the 1.8.8 line (the release became 1.8.9) and four on 2.3.0 (this one).
#   Stage 1 covered both and stage 1 does not run in a lane.
#
# Roughly 18 s, the most expensive entry here.  That is the price of the
# gate being run by the lane that breaks it rather than by the cut that
# cannot afford to.
tests/test_native_wrf_distribution.py
