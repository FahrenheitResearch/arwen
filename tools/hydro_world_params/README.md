# hydro-world-params (`rw_hydro_params`)

Global catchment parameters for the NextGen runoff modules, from open data, as
`model_attributes` rows of the HYDRO-WORLD fabric contract
(`arwen.hydro-world.fabric.v1`, `docs/dev/HYDRO-WORLD-CONTRACT.md`, crate `tools/hydro_world`).
Lane hydro-world-params. Rust, all cores (Rayon), table-driven.

## What it derives, per catchment

| Contract column | Recipe (source cited in `data/params.v1.json` and at the code) |
|---|---|
| `soil_class` (Noah-OWP isltyp) | USDA texture class of SoilGrids 2.0 sand/silt/clay over 0-30 cm (Soil Survey Manual triangle) -> STAS class; organic carbon >= 120 g/kg -> 13 ORGANIC; water / ice from WorldCover -> 14 / 16; area mode |
| `soil_b`, `soil_satdk_m_s`, `soil_satpsi_m`, `soil_smcmax`, `soil_wltsmc` | STAS row of SOILPARM.TBL (the NWM table, ngen be11a180) per cell; b = modal class, satdk and satpsi = area geometric mean, smcmax and wltsmc = area mean (hydrofabric aggregation). Alternative row `cosby1984-continuous`: Cosby et al. (1984) regressions |
| `soil_depth_m` | 2.0 m (every NextGen example packet) |
| `soil_slop` | 0.1, the uncalibrated Noah/NWM drainage coefficient SLOPE_DATA(1) (the NWM `slope` field CFE takes is this calibrated coefficient, not terrain slope); method `terrain_tan_coarse` (1 km DEM slope) stays selectable |
| `refkdt` | 3.0, the uncalibrated Noah/NWM REFKDT (Schaake et al. 1996) |
| `alpha_fc`, `k_lf`, `k_nash` | 0.33, 0.01, 0.03 (every NextGen example packet; two Nash reservoirs) |
| `max_gw_storage_m`, `gw_expon` | CONUS medians of the calibrated NWM v3.1.6 GWBUCKPARM Zmax (mm -> m) and Expon (`data/gw_prior.nwm-v3.1.6.json`, generated by `data/gen_gw_prior.py`) |
| `cgw_m_h` | NWM bucket Coeff (0.005 m3/s, the same in every NWM v3.1.6 bucket) * 3600 / catchment area |
| `giuh_ordinates` | time-area GIUH: Priority-Flood paths to the catchment outlet on Copernicus GLO-90, V = k S^0.5 with k by WorldCover class (NRCS NEH 630 ch. 15 Table 15-3), channel cells (>= 0.5 km2) as small upland gullies, area fraction per 3600 s |
| `veg_class` (vegtyp) | WorldCover area-majority class -> USGS 24-class or MODIFIED_IGBP_MODIS_NOAH (run config `veg_class_table`; tree cover -> evergreen broadleaf inside the tropics) |
| `impervious_fraction` | WorldCover built-up share |
| `elevation_mean_m`, `slope_mean_deg`, `aspect_mean_deg` | Copernicus GLO-90 zonal mean (EGM2008), Horn (1981) slope, circular mean aspect |
| `centroid_lat_deg`, `centroid_lon_deg` | divide polygon centroid (raster centroid for the DEM stand-in) |
| `soil_color` | 4 (every NextGen example namelist) |

LGAR (contract v1 has no LGAR columns; section 9 defers them to v1.1 with the LGAR owner):
`lgar_attributes.json` gives, per catchment and per SoilGrids depth layer (0-5, 5-15, 15-30,
30-60, 60-100, 100-200 cm), the dominant USDA class as the 1-based row of LGAR-C's
`vG_default_params.dat` and its theta_r, theta_e, alpha, n, Ks.

## Table-driven

`data/params.v1.json` (schema `arwen.hydro-world.params.v1`, written by `data/gen_params_table.py`)
holds every source row (DEM, soil, land cover: URL pattern, tile pattern, units, licence and
attribution) and every recipe row. A different soil or land-cover product is a new row; the
run config names the rows. `ParamTable::load` refuses a constant without a cited source.

Catchments come from a contract GeoPackage (`kind: gpkg`, EPSG:5070 or the ARWEN LAEA row,
optionally writing the fabric back with `model_attributes` filled), a geographic polygon
shapefile (`kind: shapefile`, e.g. NHDPlus V2.1 Catchment), or, where no fabric exists yet, a
DEM stand-in (`kind: dem_tessellation`: stream-link sub-basins, Priority-Flood per 1 degree tile,
id namespace 9, test only, never a contract namespace).

## Run

```
# on the build host: CARGO_TARGET_DIR and TMPDIR under your scratch
cargo build --release --offline -j 24
cargo test --release --offline -j 24
HYDRO_WORLD_DATA=/path/to/hydro-world cargo test --release --offline -j 24 -- --include-ignored  # GeoTIFF decoders vs GDAL
rw_hydro_params derive configs/rhine.json          # Rhine box, DEM stand-in catchments
rw_hydro_params derive configs/conus-russian.json  # CONUS check tile, NHDPlus catchments
rw_hydro_params derive configs/conus-oyster.json   # ngen case (a) fabric, writes a contract gpkg
python3 -I proof/compare_nwm.py RUN_DIR NWM_DIR OUT_DIR   # CONUS referee comparison (analysis)
python3 -I proof/plot_rhine.py RUN_DIR OUT_DIR            # Rhine maps and distributions (analysis)
```

Outputs in `out_dir`: `model_attributes.json` and `.csv` (contract rows, canonical order),
`lgar_attributes.json`, `catchment_diagnostics.json`, `labels_u32le.bin` + `grid.json`,
`receipt.json` (stages with seconds and parallelism, column ranges, bounds violations,
input SHA-256, data terms). `derive` exits 2 unless every row is complete and inside the
table's stated physical bounds and both engine packets (`hydro_world::derive::cfe_ini`,
`noahowp_overrides`) accept it.

Inputs fetched for the proof domains only (`proof/fetch_inputs.sh`): Copernicus GLO-90 tiles,
WorldCover v200 tiles, SoilGrids WCS subsets, under `$HYDRO_WORLD_DATA/<source>/`.

Data terms printed with every product: Copernicus WorldDEM-90 attribution, "Contains SoilGrids
2.0 data, ISRIC World Soil Information, CC BY 4.0", "(c) ESA WorldCover project 2021 / Contains
modified Copernicus Sentinel data (2021) processed by ESA WorldCover consortium".

## Proof (2026-10-18, build host, 24 threads, CPU only)

- GeoTIFF reader: Copernicus GLO-90 (deflate + floating-point predictor), WorldCover (deflate
  tiles) and SoilGrids WCS (int16) decode byte-identical to GDAL 3.10 (`tests/decoders.rs`,
  SHA-256 of the decoded arrays). Projections match PROJ to 1 mm (`proj::tests`).
- Rhine box [3.5E-12E, 45.5N-53.5N], 98 M analysis cells, 11,091 stand-in catchments: every row
  complete, finite and inside the stated bounds; whole run 7.1 s wall at about 15 cores busy.
- CONUS check tile (Russian River CA, 1,433 NHDPlus catchments) against NWM v3.1.6
  soilproperties / wrfinput / GWBUCKPARM: see `receipts/hydro-world-params/compare_nwm.json`.
- ngen case (a) fabric (5 divides, EPSG:5070) goes in and comes back as a contract GeoPackage with
  `model_attributes` that `hydro_world::check` accepts (only gap: fabric_metadata, the builder's).
