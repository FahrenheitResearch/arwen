The module is compiled **visibility-patched only**.  The patch is generated by
`tools/noahmp_wrf461_oracle/make_public_radiation.py`, which rewrites the 50
`private ::` declaration lines to `public ::` and nothing else — it asserts the
input SHA-256, and aborts unless every changed line is exactly that
substitution on an otherwise identical line.

    patched sha256  3cd3690d6455cfb8549cb41979b7e101e7436464c478f7f7973ab226488ac206

`tools/noahmp_wrf461_oracle/compare_object_code_radiation.py` proves the patch
changes no generated code.  It does **not** claim byte-identical `.o` files and
they are not byte-identical: making a procedure public turns an intra-module
`call` from a locally resolved offset into an `R_X86_64_PLT32` relocation.  What
it compares is the per-procedure disassembly with every `call` target rewritten
to the symbol it resolves to, plus every `.rodata` section:

## Which case binds which branch

`SNOW_AGE` — `sa_nosnow_zero`/`sa_nosnow_negsneqv` bind the `SNEQV<=0` reset;
`sa_cold_accum` and `sa_cold_noaccum` bind both arms of
`AMAX1(0, SNEQV-SNEQVO)`; `sa_warm_arg_pos` binds `ARG>0` (so `AMIN1` takes the
0 arm), `sa_at_tfrz_arg_zero` binds `ARG==0`, `sa_deep_cold` binds a large
negative `ARG`; `sa_bigdump_sge_neg` binds `AMAX1(0, SGE)` clamping to zero;
`sa_near_tfrz_age2_live` (TG = 272.90 K) is the only case where `EXTRA_GROWTH`
reaches an output at all — everywhere else `AGE2 = EXP(EG*ARG)` underflows
against `AGE1 + AGE3` in FP32.

`SNOWALB_CLASS` — `sc_noqsnow_*` bind `QSNOW<=0`; `sc_qsnow_below_cap`,
`sc_qsnow_above_cap` and `sc_qsnow_at_cap` bind both arms and the tie of
`MIN(QSNOW, SWEMX/DT)`.

`GROUNDALB` — `ga_soil_*` bind `IST==1`, including both arms of the `INC` clamp
and both arms of `MIN(ALBSAT+INC, ALBDRY)` (`ga_soil_col8_min_albdry` uses soil
colour class 8, where `ALBDRY-ALBSAT = 0.05` is below `INC`'s 0.11 ceiling);
`ga_lake_warm_*` bind the unfrozen-lake `powf` branch with `MAX(0.01, COSZ)` on
both arms; `ga_lake_frozen` and `ga_lake_at_tfrz` bind the frozen branch and the
`TG > TFRZ` boundary.

`SURRAD` — `sr_sunlit_forest` binds `FSUN>0`, `sr_fsun_zero_shade` binds
`FSUN<=0`; `sr_bare_vai_zero`, `sr_laisun_below_mpe` and `sr_laisha_below_mpe`
bind the small-side arm of `MAX(VAI,MPE)`, `MAX(LAISUN,MPE)` and
`MAX(LAISHA,MPE)` respectively.

`TWOSTREAM` — every case is one call, and the leaf is called twice per band per
step in the model, so both roles are bound directly: `ic=0` (direct) and `ic=1`
(diffuse) each appear in both bands.  `ts_vai_zero_*` bind `VAI==0`
(`GAP=KOPEN=1`); `ts_fveg_one_nogap` binds `FVEG=1` (`GAP=0`);
`ts_*_snow_*` bind `T<=TFRZ` with `FWET` both non-zero and zero;
`ts_chil_clamp_low`/`_high`/`_eps_from_zero`/`_eps_from_small` bind all four
`CHIL` clamp paths; `ts_lowsun_cosz_clamp` binds `COSZ < 0.001`; and six cases
bracket the `|SIGMA| < 1e-6` clamp at roughly -3e-6, -5e-7, -2.7e-7, +4e-7,
+6e-7 and +3e-6, so both signs of `SIGN(1.0e-6, SIGMA)` and both sides of the
threshold are bound.

`ALBEDO` — `ab_night_cosz_zero` and `ab_night_cosz_neg` bind the `COSZ<=0`
early exit; the day cases bind `IST=1` and `IST=2`, `TV` above and below
`TFRZ`, `QSNOW>0` and `QSNOW<=0`, `SNEQV>0` and `SNEQV<=0`, and
`ab_lowsun_fsun_clamp` binds `FSUN < 0.01`.

Three cases exist purely so the CUDA negative controls can fire, and they are
labelled as such: `ga_lake_powf_discrim`, `ts_logf_discrim_asu` and
`ts_logf_discrim_avmu`.  Their `COSZ`/`XL` were found by scanning the float32
grid on the GPU for a value where CUDA's `powf`/`logf` and the glibc
transcription produce different *leaf outputs*.  For `powf` it is not enough to
find a base where the raw call differs: `0.06/(x+0.15)` attenuates a 1-ulp
difference and it usually rounds away, so the scan compares the final `ALBSOD`.
Before those three rows existed, the CUDA `logf` and `powf` negative controls
both reported zero differing lanes — the fixture would have passed a kernel
that called CUDA's own libm.

## A defect in the source that the fixture pins rather than hides

`ALBEDO`'s initialisation loop (lines 2829-2842) zeroes every `INTENT(OUT)`
array except `FREVD`, `FREVI`, `FREGD` and `FREGI`.  On the `COSZ<=0` early
exit those four are therefore returned **undefined** — in the gfortran build,
exactly the bytes the caller passed, because an `INTENT(OUT)` array dummy is
passed by reference with no copy.  The fixture seeds all eight slots with
distinct values and records them as `frevd_in1..fregi_in2`, and the
transcriptions thread them through, so the night-time contract is pinned
bit-for-bit.  In WRF this is benign only because `SOLAD` and `SOLAI` are zero
at night, which makes `SURRAD`'s `FSRV` and `FSRG` zero regardless of what
those arrays contain.  `FAGE` behaves the same way and is recorded as
`fage_in`.

## Transcendentals

`gfortran` lowers the `EXP`, `LOG` and `**` in these leaves to glibc `expf`,
`logf` and `powf`, none of which is correctly rounded.  The transcriptions call
`gpuwm/core/noahmp_libm.py` (`logf` added by this lane; `expf`/`powf`/`f32`
came from the VEGE_FLUX lane) and, on the GPU, the `glibc_*` device functions
in `gpuwm/core/kernels/noahmp_radiation.cu`.

`tools/noahmp_wrf461_oracle/validate_radiation_oracle.py --libm-sweep` compares
those against the **live** glibc through `libm_probe_radiation.c`:

    logf  794945 arguments   0 mismatches
    expf  794963 arguments   0 mismatches
    powf  498026 arguments   0 mismatches

covering the reachable domain, every `__logf_data` subinterval boundary, and
the exact argument stream replaying all six fixtures produces.  This is **not**
exhaustive over all 2**32 patterns and does not claim to be.  Negative
controls: `--negative-control table` (one `logc` entry scaled by 1+2**-26) gives
1980 mismatches, `--negative-control numpy` (numpy float32 transcendentals)
gives 377229.  Both fire.
