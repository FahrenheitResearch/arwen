# Pinned Noah-MP WRF v4.6.1 *thermal* leaf vectors

`noahmp-thermal.csv` and `noahmp-thermal-discrimination.csv` are the fixture
for the snow/soil temperature group: **TSNOSOI, HRT, HSTEP, PHASECHANGE and
FRH2O**. They are a second, independently owned leaf group alongside
`noahmp-leaves*.csv`; the two share no writable file.

They were generated by `tools/noahmp_wrf461_oracle/build_thermal.sh` from a
scratch copy of the pinned WRF v4.6.1 tree at commit
`d66e442fccc04111067e29274c9f9eaccc3cef28`, carrying only the audited
visibility patch `patches/noahmp-lsm-leaf-visibility.patch` (50
`private ::` -> `public ::` accessibility statements and nothing else). The
pinned tree is never written to.

## Regions the routines never read

`run_thermal.F90` fills those with `POISON = -9999.0` rather than a plausible
value, so a port that reads them is visibly wrong:

* `hrt`: `ZSNSO`, `STC`, `DF`, `HCPCT`, `PHI` above `ISNOW`;
* `phasechange`: `FACT` above `ISNOW`;
* `frh2o`: every layer of `BEXP`, `PSISAT`, `SMCMAX` except `ISOIL = 1`.

`INTENT(INOUT)` entries above `ISNOW` are a different case: WRF leaves them
untouched, so they carry ordinary values, are flagged `live=1`, and the
validator asserts the echo bit for bit.

## Inert arguments

27 argument slots are declared inert, each with the WRF line that makes it so.
The zero-probe sweep requires that every one of them moves nothing anywhere,
and the mutation study requires that every one of their mutants survives while
no mutant on any consumed argument does.

The large group is `tsnosoi`: line 5346 is an unconditional `RETURN` with the
comment "Skip the energy balance check for now", and lines 5348-5369 sit behind
it. `ICE`, `IST`, `ILOC`, `JLOC`, `SAG`, `TG` and all seven `DZSNSO` entries
reach nothing that survives it.

## Branches this fixture does NOT bind

Recorded here rather than left implicit:

* `PHASECHANGE` `IF (WMASS0(J) < SUPERCOOL(J))` (5768) and the
  `MAX(MICE(J),0.0)` at 5773 are **unreachable**: 5768 sits inside `XM(J) < 0`,
  which needs `HM(J) < 0`, which under a positive `FACT` needs
  `IMELT(J) == 2`, which needs `MLIQ(J) > SUPERCOOL(J)` (5703); and
  `WMASS0 = MICE + MLIQ` with `MICE = (SMC-SH2O)*DZ*1000 >= 0`. Reaching it
  needs an `SH2O > SMC` column, which SOILWATER cannot produce.
* `FRH2O`'s Flerchinger fallback (5928-5935) needs the Newton loop to use all
  ten iterations without `DSWL` falling to `ERROR = 0.005`. A 200000-draw
  random search over the full physical box never reached it. That is evidence,
  not a proof of unreachability, and the port is labelled accordingly.
* `PHASECHANGE`'s two `IMELT` resets (5723, 5727) cannot fire at any call site,
  because `FACT = DT/(HCPCT*DZSNSO)` (2497-2499) is strictly positive, which
  ties `sign(HM)` to the `IMELT` test that produced it. Unlike 5768 they are
  bindable as a function of the argument list, so the `fact_sign_probe` case
  gives `FACT` a negative sign and both reset bodies **are** measured. That
  case is a sign probe, not weather.

CUDA was measured on an RTX 5090 (sm_120), CUDA 12.8, cupy 14.1.1, over the
same fixture and the same slot layout, 760 compared slots in total.

Four independent controls stand behind those numbers, because `max_ulp 0`
alone is not evidence:

* **Mutation study** -- 1593 mutants over the five leaves. Every mutant on a
  consumed argument is killed; every surviving mutant sits on one of the 27
  declared-inert arguments.
* **`--fmad=true` vs `--fmad=false`** -- bit-identical. HRT is dense in
  `a*b - c*d` and `-(a+b)`, so an unpinned contraction boundary would show.
* **Device ROSR12 cross-check** -- HSTEP's device-function copy of ROSR12 is
  replayed against the *already pinned* `rosr12` leaf fixture in
  `noahmp-leaves.csv`, which a different harness built from the same WRF
  source.
* **A one-ULP kernel perturbation must fail the gate** -- the same translation
  unit recompiled with HRT's 0.5 at :5444 moved by one ULP is required to be
  rejected by the fixture.

## Port side

`gpuwm/core/noahmp_thermal.py` (CPU), `gpuwm/core/kernels/noahmp_thermal.cu`
(CUDA) and `tests/test_noahmp_thermal.py`. ROSR12 is imported from
`gpuwm/core/noahmp_leaves.py` rather than re-transcribed on the CPU side; the
device side cannot import it, so `noahmp_thermal.cu` carries a device-function
copy and `test_device_rosr12_matches_the_already_pinned_rosr12_leaf` replays
the pinned `rosr12` fixture through that copy so the two cannot drift.

`noahmp_thermal.cu` is compiled after `noahmp_leaves.cu`
(`gpuwm/core/noahmp_thermal_gpu.py`): PHASECHANGE and FRH2O need glibc 2.39's
`powf` and `logf` on the device, and there must be exactly one transcription of
those, because two copies could drift and only one of them would be audited
against `glibc-libm-fp32.csv`.
